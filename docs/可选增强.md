# 可选增强：从 DeepTutor 借来的三个方向

> **定位：这是"项目完成之后"才考虑的东西，不是待办事项。**
> 现在（B4 之前）任何一条都不应该动手。写下来的目的只有一个：不丢掉想法，同时不被打断。
> 如果最后这个项目只做到「选中报错 → 三级提示」，这份文档里一条都没实现，也算完成。

---

## 来源

- [DeepTutor（HKUDS）](https://github.com/HKUDS/DeepTutor)，Apache-2.0，港大 HKUDS 团队的 agent-native 个性化学习工作区
- 它有七个学习模式（对话辅导、随堂测验、深度研究、可视化、解题、掌握度追踪、沉浸阅读）共用一套运行时，配多引擎 RAG 和[三层记忆](https://developer.aliyun.com/article/1758584)
- 一句话：它解决「我没有老师」；本项目解决「我卡住了，先别告诉我答案」。**它必须宽，本项目必须窄。**

它能长成那样，靠的是团队 + 论文 + 两年迭代。差的是规模，不是思路——所以只借结构，不借功能数量。

## 1. 错题库分三层

**原理**：记忆分 L1 原始轨迹（每次交互的原文）/ L2 摘要（一段时间内的脉络）/ L3 归纳（你是谁、什么水平、什么偏好），并且三层之间可追溯。

**本项目可以怎么做**：

```
L1  一条原始记录：时间 | 错误类型 | 位置(文件:行号) | 用到了第几级提示 | 是否自己改对
L2  按错误类型聚合：出现次数、平均用到第几级
L3  一句归纳：「空指针你基本能自己看出来；数组越界每次都卡到第三级」
```

对应规划里的 `MistakeRepository`（`PersistentStateComponent` 持久化）。

**为什么现在不做**：在「解释得对不对」还没被 20 条样本验证之前就修仓库，等于给一座没通车的桥先盖收费站。

**如果真做，验收标准**：

- L3 那句话能拿着 L1/L2 的数据一行行对出来，不是模型编的
- 断网也能算出来（纯统计，不调接口）
- 关掉 IDEA 再打开，记录还在

---

## 2. 掌握度 = 用到的提示级数

**它怎么做的**：掌握度追踪（Mastery Path），记录你在每个知识点上走到哪一步。

**本项目可以怎么做**：**不要做"掌握度百分比"**——那个数字是编的，没有任何东西支撑它。做这个：

- 每次解释，记下学生实际展开到了第几级提示（1/2/3）
- 同一错误类型连续 N 次只用第 1 级 → 可以折叠这一类的提示
- 每次都要第 3 级 → 这一类的 L3 文案值得重写，或者这个知识点该回去补

好处：`HintBook` 本来就按 level 返回，顺手记一下就有数据。

**为什么现在不做**：现在一共 7 条样本，统计出来全是噪声。**样本量不到 20 条，所有"趋势"都不可信。**

**如果真做，验收标准**：

- 能说清「连续 N 次」的 N 是怎么定的，不是拍脑袋
- 这些记录学生自己看得见

---

## 3. 记忆可审计、可编辑

**它怎么做的**：记忆不是黑箱——L1 证据、L2 摘要、L3 归纳互相可追溯，并且可编辑。

**本项目可以怎么做**：错题库做成学生**能看、能删**的列表。不是后台日志，是一个界面。

**为什么重要（这条和功能无关，和产品性质有关）**：教育类工具里，学生被"记录"这件事本身是有分量的。他得能看见「系统记了我什么」，也得能说「这条删掉」。这一点和你已经在做的脱敏（去绝对路径、姓名、学号）是同一件事的两半：一是不外泄，二是不隐瞒。

**如果真做，验收标准**：

- 列表里每一条都能单独删除
- 删完，L2/L3 跟着重算，不是留着旧结论
